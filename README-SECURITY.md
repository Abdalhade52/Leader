# مدار للتوزيع — الأدوار والصلاحيات

| الدور | الصلاحيات |
|---|---|
| الموظف | عرض كتالوج المخزون دون أسعار التكلفة/البيع، وتسجيل حركات التوزيع لفرعه فقط. |
| مدير الفرع | صلاحيات الموظف، الاطلاع على حركات وإحصاءات فرعه، وإنشاء حسابات موظفين لفرعه. |
| مدير الشركة | إدارة مخزون الشركة وفروعها وحركات التوزيع والمستخدمين، وإنشاء مديري فروع وموظفين. |
| صاحب المشروع | كامل صلاحيات الشركة، مع صلاحية إنشاء مدير شركة. |

يتم جلب الدور والفرع من قاعدة البيانات عند كل طلب، والتحقق من صلاحيات الخادم؛ إخفاء رابط الواجهة وحده لا يمنح أو يمنع الصلاحية. المستخدمون من نوع employee وbranch_manager يجب ربطهم بفرع واحد. حماية الصفوف تستخدم shop_id، وحركات الفرع تقيد بـ branch_id.

## إعداد قاعدة البيانات
خذ نسخة احتياطية قبل التعديل. للمشروع الجديد استورد schema.sql. للقاعدة السابقة نفّذ migrate_roles.sql مرة واحدة، ثم عيّن branch_id لكل حساب قديم من نوع staff/employee أو branch_manager قبل تمكينه. يتوقع ملف الترحيل أسماء قيود المفاتيح الخارجية القياسية من MySQL؛ راجعها في قاعدة البيانات قبل التنفيذ إذا سبق تعديلها.
اضبط APP_DB_HOST وAPP_DB_NAME وAPP_DB_USER وAPP_DB_PASS في إعدادات الخادم، واستخدم مستخدم قاعدة بيانات محدود الصلاحيات. في XAMPP المحلي، يمكن وضع إعدادات الاتصال في config.local.php (ويُمنع تنزيله عبر Apache ويُستثنى من Git). أنشئ أول مالك من الطرفية: php create_admin.php "اسم المنشأة" owner@example.com "كلمة مرور قوية من 12 حرفًا على الأقل". فعّل HTTPS قبل وضع بيانات حقيقية.

## تنبيهات المخزون
المخطط الجديد يتضمن min_quantity كحد إعادة الطلب. عند تحديث قاعدة قديمة نفّذ migrate_stock_alerts.sql مرة واحدة. تعرض لوحة dashboard.php مؤشرات المخزون والتوزيع وتنبيهات النقص والصلاحية، ويمكن البحث والتصفية من صفحة GEB2.php.
